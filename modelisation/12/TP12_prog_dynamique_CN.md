# TP12：动态规划

## 1 引言

在许多计算机问题中，糟糕的实现会导致计算的冗余。为了避免这类问题，可以使用一种编程方法——**动态规划**。

## 2 示例

### 2.1 示例：糟糕的编程

考虑以下程序：

```python
def suite(n):
    u = 5
    for i in range(1, n+1):
        u = i*u + 2
    return u

def calcul_liste(n):
    L = []
    for i in range(n+1):
        L.append(suite(i))
    return L
```

我们来评估这些函数的时间复杂度。对于函数 `suite`，计算 `suite(n)` 的时间复杂度为 O(n) 次基本操作。因此，计算 `calcul_liste(n)` 的时间复杂度为 O(n²) 次基本操作。

但 `calcul_liste` 并非最优：在计算 `suite(i)` 时，所有 `suite(k)`（k < i）都会被重新计算。因此，可以利用这一观察来改进复杂度。优化后的程序如下：

```python
def calcul_liste_opt(n):
    L = [5]
    for i in range(1, n+1):
        u = i*L[i-1] + 2
        L.append(u)
    return L
```

对于这个新版本，`calcul_liste_opt(n)` 的时间复杂度为 O(n) 次基本操作。

### 2.2 示例：卡特兰数列

考虑由以下公式定义的数列：

$$C_0 = 1, \quad \forall n \in \mathbb{N}, \quad C_{n+1} = \sum_{k=0}^{n} C_k C_{n-k}$$

计算前几项可得：1, 1, 2, 5, 14, 42, ...

一个朴素的递归写法如下：

```python
def catalan_naif(n):
    if n == 0:
        return 1
    else:
        S = 0
        for i in range(n):
            S = S + catalan_naif(i) * catalan_naif(n-1-i)
        return S
```

显然，这种情况下会发生组合爆炸。为避免此类问题，可以像之前一样处理：

```python
def catalan_iter(n):
    C = [1]
    for k in range(1, n+1):
        S = 0
        for i in range(k):
            S = S + C[i] * C[k-1-i]
        C.append(S)
    return C[n]
```

为了递归地解决这个问题，可以使用全局变量的字典或列表。例如：

```python
dico_cat = {0: 1}

def catalan(n):
    if n in dico_cat:
        return dico_cat[n]
    else:
        S = 0
        for i in range(n):
            S = S + catalan(i) * catalan(n-1-i)
        dico_cat[n] = S  # 非常重要：将结果存入字典
        return S
```

### 2.3 示例：整数金字塔

考虑一个自然数金字塔，例如：

```
        3
      4   2
    5   1   3
  6   3   5   2
3   8   4   3   7
  2   1   2   1   3
            4       2
```

给定一条简单路径 $C = c_1, \cdots, c_n$，满足：
- 对于所有 $i \in \{1, \cdots, n\}$，$c_i$ 是第 i 行的一个格子，
- 对于所有 $i \in \{1, \cdots, n-1\}$，$c_i$ 和 $c_{i+1}$ 是相邻的格子，

记 $S(C)$ 为 C 中所有元素的和。目标是最大化这个和 S。

第一种方法是考虑所有路径 C，计算每条路径的 S(C) 并保留最大值。但这样做的复杂度是指数级的，这类路径的数量下界为 $2^n$。

但这种做法没有优化计算。为了改进复杂度，需要寻找可以利用的递推关系。

为此，可以注意到：若记 $S_{i,j}$ 为从第一个格子开始到第 i 行第 j 个格子的路径的最大和，则有：

$$S_{i,j} = \max(S_{i-1,j}, S_{i-1,j-1}, S_{i-1,j+1}) + C_{i,j}$$

其中 $C_{i,j}$ 是格子 (i, j) 的内容，并约定若 $S_{i,j}$ 根据索引未正确定义，则取值为 0。最终所求结果为 $\max_j S_{n,j}$。

为了高效编程，可以利用递推关系，函数如下：

```python
def optimale(P):
    N = len(P)
    L = [[P[i][j] for i in range(j+1)] for j in range(N)]
    for i in range(1, N):
        for j in range(0, i+1):
            M = [0]
            for k in range(j-1, j+2):
                if (k >= 0) and (k < i):
                    M.append(L[i-1][k])
            L[i][j] = max(M) + P[i][j]
    return max(L[N-1])
```

对于有 n 行的金字塔，时间复杂度为 O(n²)。

## 3 实验作业

在本题中，一个**货币系统**是一个包含 n 个互不相同的非零自然数的集合 $D = \{d_0, d_1, \cdots, d_{n-1}\}$，其中 $n > 0$ 且 $d_{n-1} = 1$。$d_i$ 称为系统的**面额**。按惯例，面额按降序排列。例如，欧元系统是集合 $\{500, 200, 100, 50, 20, 10, 5, 2, 1\}$。

一个**（货币）金额**是一个属于 D 的整数的有限序列 $[e_0, e_1, \cdots, e_{m-1}]$。该序列的元素称为**币种**。注意，一个金额中的两个币种可以有相同的面额，一个金额可以为空，且金额中不一定包含面额为 1 的币种。按惯例，币种按面额降序排列。

一个金额 S 的**价值**，记作 val(S)，是其所有币种的算术和；而它的**大小**，记作 |S|，是其元素个数（即上述的整数 m）。给定一个自然数 v，一个价值为 v 的金额称为 v 的一个**表示**。例如，一个钱包包含三张 10 欧元钞票、两张 5 欧元钞票和一枚 1 欧元硬币，表示的金额记作 $[10, 10, 10, 5, 5, 1]$。其价值为 41，大小为 6。

一个金额 S 是另一个金额 P（称为**钱包**）的**子金额**，当且仅当 S 是 P 的子序列。例如，如果有钱包 $P = [10, 10, 10, 5, 5, 1]$，则 $S = [10, 5]$ 是 P 的子金额。

在下文中，在 Python 中：
- 一个货币系统 D 用一个严格递减、以 1 结尾的整数列表表示，
- 一个金额 S 用一个由 D 中元素组成的递减列表表示。

假设（对于参数）并保证（对于结果）以下性质：
- 列表中出现的所有整数都是严格正数，
- 所有列表按降序排列，
- 表示货币系统的列表包含互不相同的整数，且最后一个元素为 1。

### 入门

**1.** 编写函数 `valeur(S)`，接受一个金额作为参数，返回对应的价值。不使用 Python 的 `sum` 函数。

### 精确支付

在本部分中，考虑精确支付问题。根据前文的术语，即给定一个自然数 p，找到 p 的一个表示。

一种支付价格 p 的可能方法是所谓**贪心方法**，可以非正式地描述如下：
- 给出尽可能大的币种，即满足 $d \leq p$ 的最大面额 d；
- 从待支付价格中减去给出的币种，即令 $p = p - d$，然后重复。

当初始价格被完全支付时，过程终止。

**2.** 在此问题中，假设买家总是拥有所需的币种。
- (a) 证明贪心方法总能成功。
- (b) 编写函数 `glouton(D, p)`，接受一个表示货币系统的列表 D 和一个表示待支付价格的正整数 p，返回使用贪心方法得到的金额列表。

**3.** 这次考虑买家的资源限制。根据前文的术语，即找到一个价值等于待支付价格、且是给定钱包子金额的金额。
- (a) 使用欧洲货币系统 $[500, 200, 100, 50, 20, 10, 5, 2, 1]$ 举例说明：即使根据可用资源可以支付，贪心策略也可能在给定价格下失败。
- (b) 编写函数 `paye_glouton(Pf, p)`，接受一个表示金额（钱包）的列表 Pf 和一个表示待支付价格的正整数 p，返回使用贪心方法得到的、Pf 的价值为 p 的子金额。如果该方法失败，返回空列表。

**4.** 目标是计算给定钱包 Pf 支付某个价格 p 的方式数。
- (a) 编写函数 `compte_paiements(Pf, p)`，接受一个表示钱包的列表 Pf 和一个表示价格的自然数 p，返回使用 Pf 中币种支付 p 的方式数。换句话说，该函数返回 Pf 的价值为 p 的子表示的集合的基数。在此第一个版本中不追求计算优化。**注意**：面额相同的两个币种被视为不同的。因此，如果钱包是 $[2, 2, 2]$，价格为 2，则有三种支付方式。
- (b) 为优化上述函数，一种方法是使用字典。然而，列表不可哈希，不能用作键。因此，在此问题中将列表 Pf 替换为元组。编写函数 `compte_paiements_opt(Pf, p)`，接受一个表示钱包的元组 Pf 和一个表示价格的正整数 p，返回使用 Pf 支付 p 的方式数。在此版本中，可以使用字典或矩阵辅助。在所有情况下，应优化计算次数。

### 精确且最优的支付

一个金额当其在给定价值的金额集合中**大小最小**时，称为**最优金额**。例如，金额 $S = [20, 20, 1]$ 表明钱包 $P = [10, 10, 10, 5, 5, 1]$ 在价值为 41 的金额中不是最优的。实际上，S 的大小为 3，严格小于 P 的大小。

**5.** 假设 D 中每种面额的币种都有无限数量。固定一个严格正整数 p。目标是找到 p 的最优金额的大小，记作 $t(p, D)$。
- (a) 简要论证以下关系：
  - $t(0, D) = 0$
  - $\forall p \in \mathbb{N}, \quad t(p, [1]) = p$
  - $\forall p \in \mathbb{N}^\star, \quad t(p, D) = \min(1 + t(p - d_0, D), \ t(p, D \setminus \{d_0\}))$
- (b) 利用动态规划和上述递推关系，编写函数 `taille_opt(D, p)`，接受一个表示货币系统的列表 D 和一个表示价格的自然数 p，返回 p 的最优金额的大小。注意优化计算。
- (c) 改编上述函数，编写函数 `somme_opt(D, p)`，接受一个表示货币系统的列表 D 和一个表示价格的严格正整数 p，返回价格 p 的一个最优金额 S。

**6.** 在此问题中，固定一个钱包 Pf。给定一个价格 p，找到相对于钱包 Pf 的**最优金额**，即找到一个 Pf 的、价值为 p 且大小最小的子金额 S，也就是说，Pf 的任何其他价值为 p 的子金额 S' 的大小都大于 S。

借鉴前面的问题，利用动态规划，编写函数 `optimale(Pf, p)`，接受一个表示钱包的列表 Pf 和一个表示价格的自然数 p，返回相对于钱包 Pf 的最优金额。如果不存在这样的金额，返回空列表。

## 4 进阶练习

动态规划方法非常通用。以下是一些可以用该方法解决的练习。

**练习 1.** 考虑由以下公式定义的整数序列 $(u_k)_{k \in \mathbb{N}}$：

$$u_0 = 115, \quad \forall k \in \mathbb{N}, \quad u_{k+1} = 15091 \cdot u_k \bmod 64007$$

求 $u_{10}$、$u_{100}$、$u_{1000}$ 的值。

**练习 2.** 给定一个有限数列 $u_0, u_1, \cdots, u_n$，**最长递增子序列**是 $u_0, \cdots, u_n$ 的一个长度最大的递增子序列，即任何严格包含它的子序列都不是递增的。
1. 明确推导 $u_0, \cdots, u_n$ 的最长递增子序列与 $u_1, \cdots, u_n$ 的最长递增子序列之间的递推关系。
2. 编写函数 `plus_longue_ssc(u)`，返回 u 的一个最长递增子序列。

**练习 3.** 给定两个字符串 $a = a_0 \cdots a_{n-1}$ 和 $b = b_0 \cdots b_{m-1}$，a 和 b 的**最长公共子序列**是以下三种形式之一：
- $c = a_0 c'$，其中 $a_0 = b_0$ 且 $c'$ 是 $a_1 \cdots a_{n-1}$ 和 $b_1 \cdots b_{m-1}$ 的最长公共子序列，
- c 是 a 和 $b_1 \cdots b_{m-1}$ 的最长公共子序列，
- c 是 $a_1 \cdots a_{n-1}$ 和 b 的最长公共子序列。

利用这一观察，使用动态规划确定最长公共子序列。
